# TOWskill

把**一个人的说话方式**写成一个 Skill，让 AI 用"我"的语气、并按对象切换口吻来写消息。

这不是通用人格模板，而是某个人语言习惯的真实切片：什么时候话多、什么时候话少、对谁软、对谁直、用什么标点、什么时候憋笑。

---

## 它做什么

- 按**关系亲疏**自动切换语气：群聊 / 朋友 / 亲密朋友 / 对象 / 网友 / 家人 / 同学 / 导员
- 复刻**语言表层特征**：句子长度、拆条节奏、标点习惯、括号用法、语气词、颜文字与 emoji 的使用边界
- 复刻**互动套路**：怎么开口找人、怎么提请求、怎么安慰人、怎么吐槽、怎么追问
- 输出是**草稿**，供本人确认后再发

## 它不做什么（边界）

- **不代替本人对外发送消息**，也不用于冒充身份、误导他人
- 涉及政治、宗教、身份、性取向等敏感争议话题，**不模仿本人立场，也不代人撰写攻防文字**
- 不做心理状态的判断、诊断或建议
- 不编造本人不知道的观点；拿不准时标注 `[需你确认]`

---

## 目录结构

```
towskill/
├── SKILL.md                      # 主文件：场景语气表 + 规则清单
└── references/
    └── style-samples.md          # 证据库：各场景的真实原话样本
```

> `SKILL.md` 里的 YAML frontmatter 含 `name` 与 `description`。
> **目录名必须与 `name` 完全一致**（即 `towskill`），否则部分运行时无法识别。

## 安装

### 一、AstrBot

本仓库的**根目录就是 Skill 目录本身**，所以直接把整个仓库放进 Skills 路径即可：

| 范围 | 路径 |
|---|---|
| 全局（所有会话可用） | `<AstrBot 数据目录>/data/skills/towskill/` |
| 仅当前工作区 | `<工作区>/skills/towskill/` |

```bash
# 1. 克隆到临时位置
git clone <本仓库地址> /tmp/tow-skill

# 2. 复制进 Skills 目录，并确保目录名是 towskill（与 SKILL.md 的 name 一致）
mkdir -p <AstrBot数据目录>/data/skills
cp -r /tmp/tow-skill <AstrBot数据目录>/data/skills/towskill

# 3. 可选：清掉仓库附属文件，只保留 Skill 本体
rm -rf <AstrBot数据目录>/data/skills/towskill/.git \
       <AstrBot数据目录>/data/skills/towskill/README.md \
       <AstrBot数据目录>/data/skills/towskill/.gitignore
```

安装后如未立即识别，**重载一次配置**。

> 说明：`README.md`、`.gitignore`、`.git/` 都是仓库层面的文件，**不是 Skill 的组成部分**。
> 留着不影响运行，但删掉更干净。

### 二、其他支持 Skill 的 Agent

通用做法是把这个目录整体放到该 Agent 的 skills 目录下，**保持目录名为 `towskill`**：

```
<agent 的 skills 目录>/
└── towskill/
    ├── SKILL.md
    └── references/style-samples.md
```

常见位置（按你的 Agent 实际约定为准）：

- Claude Code / Claude Skills：`~/.claude/skills/towskill/`
- 其他框架：通常为 `<project>/.skills/` 或 `<project>/skills/`

### 三、纯提示词用法（任何 AI，无需安装）

没有 Skills 机制也能用——把 `SKILL.md` 的内容作为系统提示的一部分喂给模型即可：

```
下面是我的语言风格说明。请严格按它来写我要发的消息：

<把 SKILL.md 的正文粘贴到这里>
```

需要更精确时，把 `references/style-samples.md` 一并附上。

## 怎么用

安装完成后，用自然语言触发即可：

```
用我的语气写
像我一样回复
帮我想想我会怎么说
模仿我发消息
这句话我平时会怎么讲
帮我回这条
```

或者直接点名：

```
用 TOWskill 的语气
像 TOW2A 那样写
```

### 举例

**给导员请假**（语气层：官方对象）

```
导员
下周三下午有课吧
我打算周三去市里一趟
当天回来
```

> 该场景的特征是：**不出现"请假"二字**，先问前提，再报安排，把结论留给对方。

## 已覆盖的场景

| 场景 | 语气特征 |
|---|---|
| 熟人群聊 | 短、碎、围观式 |
| 普通私聊 | 直接、请托不客套 |
| 朋友（有内部梗） | 用昵称当主语、跟着对方的梗演 |
| 亲密朋友 | 波浪号密集、直白表达感情 |
| 对象 | 撒娇、讨回应、情绪直给 |
| 半熟网友 | 随和、卖萌、但爱催 |
| 家人 | 极短确认、直接反驳、不把话说满 |
| 刚加的陌生同学 | 零寒暄、一个词顶回去 |
| 情绪低落 | 短句排比递进、一条一断 |
| 群聊冲突／辩论 | 点名、反讽、归谬，不上脏话 |
| 官方对象（老师、导员） | 极简、裸称呼起手、零客套 |

## 关于隐私与语料

- 仓库内的样本**已做脱敏**：昵称、群名、班级、就读信息等已替换为占位符（如 `[昵称]`、`[班级]`），涉及他人私事的示例已泛化处理
- **原始聊天记录不入库**，仅保留提炼后的规则与样本
- 样本来源均为本人主动提供

### 想做一个"像自己"的版本

1. 先搭一个空 Skill 骨架（`SKILL.md` + `references/style-samples.md`）
2. 持续投喂**你亲手写的**聊天记录、邮件、朋友圈，越多场景越好
3. 让 AI 从中提炼**可执行的规则**，而不是形容词
4. 每一条规则都要**注明证据**（来自哪段对话），没有证据的部分标 `[待填]` / `[待确认]`
5. 定期实测：让 AI 写几段，你挑毛病，把差异**反向写回规则**

> 经验之谈：真正值钱的修正往往来自"**我不这么说**"这五个字。语料能提取用词，但格式层和边界层的习惯（比如"拆条"到底是发三条消息还是一条消息换三行），只有本人能发现。
